Caffeum(CafeumOffice.csproj, v1.1.6, .NET 9 · Windows Forms)을 만들고 나서 코드를 천천히 읽으며 C#을 공부하기 위한 페이지예요. 파일 31개 · 약 3만 1천 줄에서, 읽기 쉬운 곳부터 순서대로 고르고, 각 개념이 실제로 어디에 쓰였는지 줄 번호로 짚어 둡니다.

카드의 "읽었음"을 체크하면 이 브라우저에 기억돼요. 줄 번호는 지금 코드 기준이라, 코드가 바뀌면 조금 어긋날 수 있어요.

2. 코드로 배우는 C#

교재 예제가 아니라 Caffeum에 실제로 있는 코드예요. 이미 동작하는 코드라서, 읽다가 이해가 안 되는 줄은 그대로 AI에게 물어보거나 줄을 바꿔 보며 확인할 수 있어요.

파일 범위 namespace 쉬움

거의 모든 파일 첫 줄 · Scripts/Core/NaturalStringComparer.cs:1

namespace CoffeeViewer;

public sealed class NaturalStringComparer : IComparer<string?>
{
    ...

namespace 이름;(세미콜론으로 끝)은 "이 파일의 모든 것이 이 이름 공간에 속한다"는 뜻이에요. 중괄호로 한 번 더 감싸지 않아도 돼서 들여쓰기가 한 단계 줄어요. RootNamespace가 CoffeeViewer라서 앱 이름(Caffeum)과 코드 속 이름이 다른 점도 알아 두세요.

sealed는 "이 클래스를 상속해 새로 만들 수 없다"는 표시예요. 이 프로젝트의 클래스 대부분이 sealed인 건, 상속할 계획이 없다는 걸 코드로 밝혀 두는 습관이에요.

// Scripts/Core/AppShared.cs
vaultPath ??= PickVaultFolder(null);   // 비어 있을 때만 폴더 고르기 창을 띄운다

.csproj에 <Nullable>enable</Nullable>가 켜져 있어서, 타입 뒤의 ?는 "null일 수 있음"을 뜻해요. string은 null이 아니어야 하고 string?은 null이 올 수 있어요. 컴파일러가 null 검사를 빠뜨리면 경고로 알려 줘요.

??는 "왼쪽이 null이면 오른쪽 값", ??=는 "왼쪽이 null일 때만 오른쪽 값을 대입"이에요.

해 보기 프로젝트에서 ??를 검색해서 몇 군데 쓰이는지 세어 보세요. 같은 일을 if (x == null) x = ...;로 쓰면 어떻게 되는지 직접 바꿔 써 보세요.

자동 속성과 기본값 쉬움

Scripts/Core/AppSettings.cs:35-46

public sealed class AppSettings
{
    public string Theme { get; set; } = "카페 라이트";
    public int    FontSize { get; set; } = 11;
    public int?   EpubMarginTop { get; set; }   // int? = 값이 없을 수도 있는 정수
    public bool   TxtWordWrap { get; set; } = true;

{ get; set; }이 붙은 건 속성이에요. 내부에 숨은 변수를 컴파일러가 만들어 주고, 뒤의 = 값이 처음 값이에요. 설정을 저장한 파일에 항목이 없어도 이 기본값이 쓰여서, 새 설정을 추가해도 옛 설정 파일이 깨지지 않아요.

int?는 null을 가질 수 있는 정수예요. 여기서는 "사용자가 따로 정했나, 아니면 기본 규칙을 따를까"를 구분하려고 써요(주석: 비어 있으면 위의 값을 쓴다).

해 보기 설정 항목 하나(예: SlideshowSeconds)를 골라, 어떤 파일들이 Settings.SlideshowSeconds를 읽는지 "모든 참조 찾기"(Shift+F12)로 따라가 보세요.

enum과 JSON 저장 쉬움

Scripts/Core/AppSettings.cs:8-29, 83-86, 195-222

public enum NovelReadingMode { Scroll, Page, PageTouch }

[JsonConverter(typeof(JsonStringEnumConverter))]
public NovelReadingMode NovelReadingMode { get; set; } = NovelReadingMode.Scroll;

public static AppSettings Load()
{
    try
    {
        if (File.Exists(FilePath))
            return JsonSerializer.Deserialize<AppSettings>(File.ReadAllText(FilePath), JsonOptions) ?? new AppSettings();
    }
    catch { /* 깨진 설정 파일은 무시하고 기본값으로 */ }

}

enum은 "정해진 몇 가지 중 하나"를 이름으로 표현해요. 숫자 0, 1, 2 대신 Scroll, Page로 쓰니 읽기 쉬워요. [JsonConverter(...)]처럼 대괄호로 붙이는 건 특성(attribute)이고, 여기서는 JSON 파일에 숫자 대신 이름으로 저장하라는 뜻이에요.

설정 클래스를 통째로 Serialize(객체→글)하고 Deserialize(글→객체)하는 구조예요. Load는 실패해도 앱이 죽지 않도록 try/catch로 감싸고 기본값을 돌려줘요.

StartListener()(197줄)는 별도 스레드에서 계속 기다리다가, 받으면 BeginInvoke로 화면 스레드에 일을 넘겨요. 처음엔 흐름만 따라가도 충분해요.

다른 스레드에서 화면 스레드로 돌아오기 어려움

Scripts/Reader/Tts.cs:39-58 · Program.cs:197-221

ui = SynchronizationContext.Current;                  // 화면(UI) 스레드를 기억해 둔다
synth.SpeakCompleted += (_, e) =>
{
    if (e.Cancelled || e.Prompt != current) return;   // 취소되었거나 이미 지난 문장이면 무시
    var done = e.Prompt;
    ui?.Post(_ =>
    {
        if (done != current) return;
        current = null;
        SentenceFinished?.Invoke();
    }, null);
};

Windows Forms 화면은 화면 스레드에서만 만지는 규칙이 있어요. 음성이 "문장 하나 끝났다"고 알려 주는 쪽은 다른 스레드일 수 있으니, Post로 화면 스레드에 일을 던져요. 신호가 겹치거나 늦게 도착해도 done != current로 걸러내는 부분이 이 코드의 핵심이에요.

공부 순서로는 가장 나중에 읽어도 돼요. "UI는 UI 스레드에서만"이라는 한 줄만 먼저 기억하세요.

윈도우 기능 직접 부르기: DllImport 어려움

Scripts/Core/Themes.cs (DllImport 선언부)

[DllImport("dwmapi.dll")]
private static extern int DwmSetWindowAttribute(IntPtr hwnd, int attr, ref int value, int size);

.NET이 제공하지 않는 윈도우 기능(예: 제목 표시줄을 어둡게)은 윈도우 자체의 함수를 직접 불러 써요. extern은 "구현은 밖(DLL)에 있다"는 뜻이고, 함수 이름과 인자는 윈도우 문서의 것을 그대로 옮겨 적어요. 이런 선언은 이해하려 하기보다 "이런 게 있다"만 알아 두면 돼요.

5. 용어 모음

속성 (property)
{ get; set; }이 붙은 값. 변수처럼 쓰지만 읽고 쓸 때 규칙을 붙일 수 있다.
특성 (attribute)
[JsonConverter(...)]처럼 대괄호로 붙여 코드에 정보를 더하는 표시.
람다식
x => x.Name 형태의 이름 없는 짧은 함수.
제네릭
List<string>의 <string>처럼 "어떤 종류를 담을지"를 끼워 넣는 방식.
LINQ
목록을 걸러 내고 바꾸고 정렬하는 메서드 모음(Where, Select, OrderBy …).
UI 스레드
화면을 그리고 클릭을 처리하는 한 줄기 실행 흐름. 화면 요소는 여기서만 만져야 한다.
이벤트 (event)
"일이 생겼다"를 알리는 장치. +=로 구독하고, 일으키는 쪽이 Invoke로 부른다.
Windows Forms
버튼, 텍스트 상자, 창을 코드로 만드는 윈도우용 화면 도구. Form이 창, Control이 화면 부품이다.
